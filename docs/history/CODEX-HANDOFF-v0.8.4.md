# Przekazanie JARVIS OS 0.8.4

Zacznij od 00_START_HERE.md, AGENTS.md, PROJECT_STATUS.json, docs/DECISIONS.md i docs/NEXT_TASKS.md. Rozwijaj istniejący projekt; następne zadanie to R05 — odczyt czujników i laboratorium MQTT. Produkcyjna AutoLogika pozostaje read-only. Wszystkie 11 obszarów i zatwierdzone decyzje obowiązują.

R01: 30 syntetycznych przypadków recepcji, runner i raporty, jakość realnego modelu niesprawdzona. R02: zamknięte deklaracje pamięci pl-declarations-v1, źródła, korekty, deduplikacja i jawne zastąpienie; domyślnie manual. R03: ręczny półdupleks PCM→Wyoming STT→domyślny review→oddzielny czat voice→TTS, test Chromium z syntetycznym mikrofonem/usługami. Głos nie wykonuje parserów ani zapisu pamięci. Realne modele/sprzęt, wake-word i prywatne wyjście pozostają oczekujące.

R04: jarvis/telephony_adapter.py definiuje ścisłe komendy kanałów i czysto laboratoryjny ACK, bez sieci. jarvis/telephony_transport.py zapisuje stan, zdarzenia i outbox w SQLite razem z recepcją przez *_in_transaction. Publiczna projekcja ma allowlistę pól, token klienta jest ograniczony do rozmowy i przechowywany jako skrót. Czas jest serwerowy, maksymalnie jedna próba, ograniczenia kosztu są symulowane. Właściciel musi dostać ofertę i zaakceptować bieżącą próbę; polityka jest ponownie sprawdzana przy zgodzie i dostarczaniu mostu. Timeout/odmowa/awaria nie ponawiają kontaktu. Stare akcje właścicielskiego laboratorium nie mogą modyfikować powiązanej recepcji. Schema11, backup i testy migracji 10→11 zachowują dane.

Panel Transport · laboratorium ma trzy oddzielne karty. Caller fetch wysyła tylko X-Jarvis-Call-Token, nigdy klucz właściciela. Token jest wyłącznie w pamięci; nawigacja/wylogowanie sprząta stan i spóźnione odpowiedzi. Zakończony test można usunąć wraz z danymi recepcji i tokenem. To nadal strona właściciela; klientowi udostępnia się tylko ograniczony kanał API, nie cały Control Center. Kontrakt i dokładne frazy testowe: [TRANSPORT-TELEFONII.md](TRANSPORT-TELEFONII.md).

Nie podłączaj tego jako gotowej telefonii. Dispatch jest ręczny, terminy aktualizują się przy odczycie/zdarzeniu, brak workera. Tylko trzy pełne frazy mają etykiety laboratoryjne; nie używaj starej heurystyki słów kluczowych dla nieufnego kanału klienta. Brak PSTN/SIP, routingu audio, webhooków operatora i niezawodnego dostarczania zewnętrznych skutków. Dalszy adapter wymaga projektu idempotencji/recovery i osobnej aktywacji. Nie wysłano rozmów ani powiadomień i nie uruchomiono urządzeń.

Sprawdzenia: 276 pytest Python3.12, pip check, składnia7 plików JS, 6 testów panelu transportu i regresja istniejących testów JS. Rzeczywisty Chromium: pełny przepływ transportu, 13 izolowanych żądań klienta, brak wycieków, DELETE→401, cleanup i szerokość390px; ponowna regresja syntetycznego głosu (2 tury, wszystkie zasoby zamknięte). Opcjonalne skrypty node scripts/check_transport_browser.cjs i node scripts/check_voice_browser.cjs wymagają Playwright/Chromium; JARVIS_BROWSER_EXECUTABLE wskazuje plik przeglądarki. Testy nie oznaczają realnego AI lub sprzętu. Windows/Docker/GitHub CI nie wykonano.

Pracuj autonomicznie na danych syntetycznych. Każdy commit musi zawierać aktualizację README z zakresem, wykonanymi sprawdzeniami i ograniczeniami. Nie obiecuj bezterminowej pracy w tle. Przed pierwszą zmianą rozpakowanego przekazania sprawdź manifest; potem jest historycznym checksumem. scripts/package_handoff.py generuje ZIP z nowym manifestem z czystego repo po commicie. Nie pakuj baz, sekretów, środowiska ani modeli. Zmiany tej sesji są lokalne, bez push na GitHub.

Dokładny wynik: docs/RAPORT.md. Poprzednie przekazanie: docs/history/CODEX-HANDOFF-v0.8.3.md. Stan wszystkich modułów: PROJECT_STATUS.json.
